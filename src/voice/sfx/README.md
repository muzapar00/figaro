# Figaro UI sound effects module

`createSfx({ config, logger })` — play short UI sounds ("earcons") without ever
touching the voice path.

```js
import { createSfx } from './src/voice/sfx/index.js';

const sfx = createSfx({ config });
sfx.play('listenStart');                 // event name → honours config.sfx.events.*
sfx.play('dismiss', { volume: 0.8 });    // sound name, extra gain multiplier
sfx.enabled;      // true only if sounds loaded AND a player AND sfx.enabled
sfx.names();      // ['answer-done','dismiss','error','listen-end','listen-start']
sfx.stats;        // plays, failures, skipped, lastPlayedAt, lastPlayedMs, sink, command, ...
```

- `play()` is async and **never throws / never rejects**; failures are silent
  (`stats.failures++`, one `log.warn` per distinct problem). It also never
  interrupts speech: every sound is its own short `pw-cat` process that
  PipeWire mixes, it does not go through TTS/MiniMax.
- No sound card? no assets? broken player? `play()` resolves with
  `{ played: false, reason }` and the daemon keeps working.
- The module reuses the tested playback helpers from the TTS module
  (`../tts/player.js` for the `pw-cat` command, `../tts/pcm.js` for PCM
  normalisation, `../tts/sink.js` for sink probing) but never creates a TTS
  client.

## Config fields (for `src/config.js` — owned by the Lead)

```js
sfx: {
  enabled: true,        // false => play() is a no-op
  volume: 0.35,         // 0..1 master gain (default 0.35)
  // per-sound gain multiplier, e.g. { 'answer-done': 0.8 } (default 1)
  volumes: {},
  // playback device: null/undefined => config.tts.sink (the voice sink);
  // "" => system default; full sink name or unique substring also works.
  sink: null,
  // optional asset directory override; default <repo>/assets/sfx
  dir: null,
  latencyMs: 40,        // pw-cat --latency
  throttleMs: 40,       // ignore a repeated identical sound inside this window
  events: {
    // camelCase event -> true (use the default sound), false (disabled),
    // or an explicit sound name to remap.
    listenStart: true,  // -> listen-start.wav
    listenEnd: true,    // -> listen-end.wav
    answerDone: true,   // -> answer-done.wav
    dismiss: true,      // -> dismiss.wav
    error: true,        // -> error.wav
  },
}
```

Defaults are applied inside the module, so a partial `sfx` block (or no `sfx`
block at all) works. `sfx.sink` falls back to `config.tts.sink`; if neither is
set, the system default sink is used (and the module logs which sink it resolved,
including the `tts.sink` alias resolution — e.g. `"hdmi"`).

Logging: one line on creation, e.g.

```
[sfx] playing to alsa_output.pci-0000_01_00.1.hdmi-stereo
[sfx] loaded 5 sounds from ~/Projects/figaro/assets/sfx/
```

Pass `logger: <daemon logger>` to route those lines through the daemon's logger,
or `logger: null` to silence the module (tests do this).

## Suggested daemon triggers

| event | where in `src/daemon.js` | notes |
|---|---|---|
| `listenStart` | `beginWakeFlow()` — right before/at `ack.play()` / `setState('waking')` | the blip occupies the ack's ~100 ms leading silence; it sits above the male voice band so it does not mask the words |
| `listenEnd` | `handleAsrFinalizing()` when ASR enters `finalizing`, or push-to-talk release | very quiet; skip it if the wake flow is tight |
| `answerDone` | when the reply truly finished: `startFollowUpWindow()` before `setState('waiting')`, or the no-follow-up path after `await voice.tts.flush()` | must be after playback, not after synthesis |
| `dismiss` | user-initiated cancel/dismiss (`cancelCurrent()` callers: cancel phrases, UI cancel, 退下) | don't fire it for internal wake-supersede cancels unless that is the desired feel |
| `error` | `handleVoiceError()` (TTS/ASR module errors), failed ask | keep it for real errors; throttle already limits repeats |

All five are fire-and-forget: call `sfx.play('answerDone')` **without awaiting**
on the hot path, and never let an SFX failure change daemon state.

## Assets

`assets/sfx/` holds five 32 kHz mono 16-bit WAVs generated by
`assets/sfx/generate.py`; measured levels / design rationale are in
`assets/sfx/README.md`. Summary: 65–200 ms, peaks -15…-17.5 dBFS, and 4–6.5 dB
below the TTS voice at the default volume.

## Tests

```bash
node --test "tests/sfx/*.test.js"   # hermetic: fake player writes PCM to a file
```

Covers: names/levels, PCM written is exactly the asset scaled by volume,
per-call and per-sound volume, `enabled:false` no-op, missing assets (silent +
`stats.failures++`), unknown names, `events.*` disable/remap, throttling, muted
volume, spawn failure / non-zero exit, `--target` from `tts.sink` (and `sfx.sink`
override), WAV decoding errors, `scaleS16` clamping.
